
### Phase 2: Create/Modify UI Component

Use `INTEGRATION_GUIDE.md` to:
1. Create `environment-tab.component.ts` in `src/app/ui/inspector/`
2. Add it to inspector tab list in `src/app/ui/inspector/inspector.component.ts`
3. Wire keyboard shortcuts (V for Director View, E for door interaction)

### Phase 3: Integrate into Existing Services

Use `INTEGRATION_GUIDE.md` to modify:
1. `src/app/render/three-scene.service.ts` — instantiate & initialize EnvironmentService
2. `src/app/drivers/driver-mixer.ts` — feed locomotion into avatar position
3. `src/app/recording/recording.service.ts` — auto-exit Director View on Record (1 line change)

### Phase 4: Blender Build (Optional, Your Computer)

**Only if you have Blender 4.0+:**

```bash
# 1. Export apartment data
node scripts/export-apartment-data.mjs

# 2. Build Blender assets
blender --background --python tools/blender/build_apartment.py

# 3. Verify output
ls public/environments/apartment-default/
```

**If Blender is not available:** Skip step 4. The app will use the procedural TypeScript builder (works perfectly, no visual difference for v1).

### Phase 5: Test

See **Testing Checklist** in `INTEGRATION_GUIDE.md`. All tests should pass with or without the Blender GLB.

## Fallback Safety

**If Blender GLB is missing:**
- App checks for `public/environments/apartment-default/scene.glb`
- If not found, `EnvironmentService` loads procedural builder automatically
- `PhysicsWorldService` uses procedural collision (not GLB-derived)
- All gameplay works identically; only visual detail is lower

**Result:** Feature is production-ready **without Blender**. Blender is an optional enhancement.

## Known Limitations (v1)

| Limitation | Reason | Workaround |
|-----------|--------|-----------|
| Single apartment layout | Scope: v1 ships one design | Environment Library (v1.2) enables import of others later |
| No 6DOF phone position tracking (except WebXR) | Web browser limitation | Selfie-stick pivot model sells rotation-only effect convincingly |
| No true collision for hand gestures | Out of scope | Hands don't collide with furniture (avatar is torso-tracked) |
| No navmesh, no stairs/ledges | Design choice: 1-bedroom apartment | Works perfectly for the space; future apartments may add terrain |
| No dynamic physics objects | Scope limit | Walls/doors/furniture are static; player is dynamic sphere |

## Support & Debugging

**Q: Apartment doesn't load.**  
A: Check browser console for errors. Verify `ApartmentBuilder.createDefaultApartment()` returns valid data.

**Q: Physics is glitchy or avatar sinks.**  
A: Ensure `cannon-es` is installed. Check `world.step()` frequency matches frame rate (1/60 default).

**Q: Blender script fails.**  
A: Run `node scripts/export-apartment-data.mjs` first. Verify Blender 4.0+ is installed and in PATH.

**Q: Recording captures Director View accidentally.**  
A: This shouldn't happen — the rule is Director View auto-exits on Record. Check the `recording.service.ts` integration (1-line change in INTEGRATION_GUIDE).

**Q: Markers don't show up in Placed Cam.**  
A: Markers are generated from `ApartmentDef.markers`. Ensure `apartment-data.json` includes them before running Blender.
